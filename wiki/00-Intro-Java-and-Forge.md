# 📖 מבוא: Java ו-Forge למתחילים

לפני שנתחיל לכתוב קוד — בואו נבין את הבסיס. אם אתם חדשים לגמרי, קראו את העמוד הזה
עד הסוף; הוא יחסוך לכם הרבה בלבול בהמשך.

---

## ☕ מה זה Java?

Java היא שפת תכנות. Minecraft (הגרסה של המחשב, "Java Edition") **כתובה ב-Java**,
ולכן גם מודים נכתבים ב-Java. כמה מושגי יסוד שנשתמש בהם כל הזמן:

| מושג | הסבר בפשטות |
|---|---|
| **Class (מחלקה)** | "תבנית" שמכילה קוד. כל קובץ `.java` הוא בדרך כלל class אחד. |
| **Method (מתודה)** | פונקציה — קטע קוד שעושה משהו, למשל `useOn(...)`. |
| **Field (שדה)** | משתנה ששייך למחלקה, למשל `public static final ... SAPPHIRE`. |
| **`static`** | שייך למחלקה עצמה, לא ל"עותק" ספציפי — אפשר לגשת בלי ליצור אובייקט. |
| **`final`** | ערך שלא משתנה אחרי שהוגדר (קבוע). |
| **`public` / `private`** | מי יכול לגשת: `public` = כולם, `private` = רק המחלקה עצמה. |
| **`import`** | מביא מחלקה מחבילה אחרת כדי שנוכל להשתמש בה. |
| **`package`** | "תיקייה לוגית" של מחלקות, למשל `net.bullettrain.tutorialmod.item`. |
| **`ModsItems`** | במוד שלנו מחלקת הפריטים נקראת **`ModsItems`** (עם s) — לא `ModItems`. |
| **`@Annotation`** | הערה מיוחדת שמתחילה ב-`@`, נותנת הוראות למערכת (למשל `@Override`). |

> 💡 לא צריך להיות מומחי Java כדי להתחיל. תלמדו תוך כדי — כל שלב מסביר את הקוד שלו.

## 🔨 מה זה Forge?

**Forge** הוא ה-*modding framework* — שכבת ביניים בין המוד שלכם למשחק. הוא נותן לכם
"ווים" (hooks) ו-API מסודר כדי להוסיף פריטים, בלוקים, יצורים וכו', בלי לשנות את קוד
המשחק המקורי ישירות.

### מושגי Forge מרכזיים
| מושג | הסבר |
|---|---|
| **`@Mod`** | ה-annotation שמסמן למחלקה שהיא נקודת הכניסה של המוד. |
| **Registry** | "פנקס רישום" — כל פריט/בלוק חייב להירשם כדי שהמשחק יכיר אותו. |
| **`DeferredRegister`** | דוחה את הרישום עד שהמשחק מוכן — כך נמנעות קריסות. |
| **`RegistryObject`** | הפניה לפריט/בלוק שנרשם, נשתמש בו כדי לגשת אליו. |
| **`IEventBus`** | "אוטובוס אירועים" — מעביר אירועים בין Forge למוד. |
| **Event** | אירוע במשחק (טעינה, שבירת בלוק וכו') שאפשר "להאזין" לו. |

## 📁 מבנה פרויקט מוד טיפוסי

```
forge-1.20.1-tutorial/
├── build.gradle            # הגדרות בנייה + תלויות (dependencies)
├── gradle.properties       # גרסאות (Minecraft, Forge, המוד)
├── settings.gradle
├── gradlew / gradlew.bat   # ה"מריץ" של Gradle (לא צריך להתקין Gradle ידנית)
└── src/main/
    ├── java/net/bullettrain/tutorialmod/   # קוד ה-Java של המוד
    │   ├── TutorialMod.java            # נקודת הכניסה (@Mod)
    │   ├── item/                       # פריטים
    │   └── block/                      # בלוקים
    └── resources/
        ├── META-INF/mods.toml          # "תעודת הזהות" של המוד
        └── assets/tutorialmod/         # מרקמים, מודלים, שפות, מתכונים...
            ├── textures/
            ├── models/
            ├── blockstates/
            └── lang/
```

**החלוקה החשובה:**
- `java/` = **הלוגיקה** (קוד שרץ).
- `resources/assets/` = **המשאבים** (איך דברים נראים — תמונות, מודלים, שמות).
- `resources/data/` = **הנתונים** (מתכונים, loot tables, tags — נראה בשלבים הבאים).

## ⚙️ מה זה Gradle?

**Gradle** הוא כלי הבנייה. הוא מוריד את Forge ואת התלויות, מקמפל את הקוד, ומריץ את
המשחק לפיתוח. לא צריך להתקין אותו — משתמשים ב-`gradlew` שמגיע עם הפרויקט.

### פקודות שנשתמש בהן
```bash
./gradlew runClient    # מריץ את Minecraft עם המוד שלכם (הכי שימושי)
./gradlew build        # בונה קובץ JAR מוכן להפצה
./gradlew --refresh-dependencies   # מרענן תלויות אם משהו נתקע
```

> ב-Windows אפשר להשתמש ב-`gradlew.bat` במקום `./gradlew`.

## 🎯 איך ללמוד עם ה-Wiki הזה

1. **עברו לפי הסדר** — כל שלב מסתמך על הקודם.
2. **קראו את ההסבר שורה-אחר-שורה** — אל תעתיקו בלי להבין.
3. **הריצו אחרי כל שלב** — `./gradlew runClient` ותראו את התוצאה במשחק.
4. **תתנסו** — שנו ערכים (חוזק בלוק, כמות XP) ותראו מה קורה.
