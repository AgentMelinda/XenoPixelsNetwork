# Combat V3 BT3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. The owner must review this plan and select the execution method before product implementation. Native execution in this session is recommended because targeting, gestures and motion share state invariants; it avoids repeatedly reconstructing those invariants. Do not dispatch implementation agents before the owner's execution choice.

**Goal:** Deliver selectable V3 combat with native DMZ left taps, stamina-heavy right taps, retained charged attacks, functional configurable Dragon Dash through 999 blocks, and every distinct attack from the supplied BT3 Part 1 showcase with its own matching choreography.

**Architecture:** Add V3 beside existing controllers. Separate gesture intent, server target ownership, resources, movement and technique timelines; share verified low-level DMZ adapters rather than the V2 attack controller. Catalog and animation work depend on that same runtime, so this is one dependency-ordered plan with a repeated per-attack delivery unit.

**Tech Stack:** Java 21; Minecraft 1.21.1; NeoForge 21.1.248; DragonMineZ 2.1.3; Gson; existing DMZ animation/projectile integration and AAA Particles.

**Spec:** `docs/superpowers/specs/2026-10-07-combat-v3-bt3-design.md`, approved by the owner on 2026-10-07. Read both documents before execution.

## Review Focus

1. A press crosses the hold threshold exactly as the lock disappears: no native tap, stale charge or duplicate release may occur (Task 4).
2. A target remains loaded on the server but disappears from client entity tracking during a long dash: UUID lock remains authoritative and does not select a reused entity ID (Task 3).
3. A heavy hit is refused by protection, dodge or guard/damage cancellation: resource cost is charged at most once, victim drain only after accepted damage (Task 5).
4. A mode switch, disconnect or failed projectile charge interrupts a cinematic while the player was flying: motion/camera/grab/chunk ownership is released once (Tasks 7 and 10).
5. A duplicate technique ID or hot reload meets an existing third-party definition: fail that owned registration without overwriting any external data or invalidating old selections (Task 9).
