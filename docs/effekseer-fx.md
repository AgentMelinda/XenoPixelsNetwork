# Effekseer effects (AAA Particles)

**Added:** 2026-09-28. Punches, Hakai and missiles play Effekseer `.efkefc` effects through
**AAA Particles 2.3.1** (MIT, mod id `aaa_particles`, required on server and client). For these
uses they replace the vanilla sparks, flames and clouds. The vanilla particles return only when an
effect does not play: the config is off, the per-tick cap was reached, or the library failed.
Design: `docs/superpowers/specs/2026-09-28-effekseer-fx-design.md`.

**2026-10-07 wave impact anchor:** DMZ 2.1.3 creates its KiWave explosion visual half a block
below the actual impact. A narrow spawn mixin marks those visuals, and the AAA KI_IMPACT
replacement restores that half block so Kamehameha effects are anchored at the impact. Other
explosion sources keep their native positions. When AAA ki impacts are disabled or unavailable,
the DMZ visual and its native position remain unchanged. No effect asset or damage radius changes.
A fresh server GameTest on 2026-10-07 exercised the native wave termination method, visual join
and marked-origin mixin and captured the AAA request at the exact impact coordinates. It also
checked ordinary and disabled-AAA fallback anchors. Particle rendering itself remains unverified.

## Slots

Each effect lives at `assets/xenopixelsmod/effeks/<slot>/<slot>.efkefc`, with its textures,
materials and models next to it under the same relative paths. **To replace an effect**, save your
own effect under the same name in that folder. No code change is needed.
**Every file and folder name must be lower case** (for example `parts/aura.png`, not
`Parts/Aura.png`), including the texture paths saved inside the effect: Minecraft rejects
upper-case resource paths and the effect then fails to load (2026-09-28: every stand-in but the
thruster failed this way). `EffectAssetsTest` checks it.
`EffectAssetsTest` checks that every slot and every file it references exists.

| Slot | When | Where |
| --- | --- | --- |
| `punch_impact` | Light DMZ hits: player or NPC, combos, rushes, basic melee | Target mid-height, along the blow |
| `punch_heavy` | Finishers, charged hits, slams; ultimate hits 1.6× larger | Same, 1.6× |
| `punch_guard` | Hits absorbed by guard | Same |
| `hakai_channel` | Every 10 ticks while Hakai channels (player and NPC) | The victim's feet, sized to its height |
| `hakai_crumble` | Every 4 ticks while the body wipe is on the body | The dissolve line (the same height the client wipe draws), sized to its width |
| `hakai_palm` | With each channel pulse | The caster's raised palm |
| `hakai_erase` | The erase | Target centre, sized to its height |
| `missile_explosion` | Every detonating tube missile warhead, and ship missile arrival | Centred on the impact, upright, sized by blast power |
| `missile_thruster` | Every 8 ticks while a tube missile's motor burns | **Bound to the missile**: AAA keeps it at the tail and turns it along the missile's velocity every frame; the smoke it sheds stays behind as the trail |
| `ship_thruster` | Every 8 ticks while a ship thruster block is lit (staggered per block) | Its nozzle in world space (through the Sable ship pose), along the exhaust, sized 0.4-1.0 by throttle |
| `sparking_aura` | Every 10 ticks while a player is Sparking | The feet, sized to the body |
| `sparking_burst` | When Sparking starts | The feet |

## Missile explosion and bound plume (generated, 2026-09-29)

- **`missile_explosion`** (set `explosion`) follows the owner's reference picture
  `tools/new_particles/on_explostion_of_missile_particle_iwant.png`:
  - a white-hot flash, an orange fireball and a lumpy grey smoke cloud;
  - orange flame rays, and about 160 streaking sparks (directional billboards);
  - about 260 embers in white, yellow, orange and red, flung out and arcing down.

  It is sent upright. The old stand-in was sent facing up, which AAA turns into a 90° tip, so its
  particles shot off to one side.
- **The missile plume is bound to the missile.**
  - AAA 2.3.1 (`ParticleEmitterInfo.spawnInWorld`) moves a bound effect with the entity and turns
    its local +Z along the entity's velocity, but only when an entity-space offset is set, and it
    adds any absolute position on top.
  - So `AaaEffekSender` binds with offset (0,0,0) and no position, and sends the packet itself
    only to players within `effekseerMissileRange`.
  - The plume hangs 1.25 effect units behind the centre, pointing along -Z, at scale 0.4 × missile
    length, which puts it at the tail.
- **Ship missiles and thruster blocks** are not entities, so they use the positional
  `ship_thruster`.

## Thruster and Sparking effects (generated, 2026-09-29)

These are generated by `python tools/effekseer/gen_effects.py thruster sparking`; see
`tools/effekseer/README.md`.

- **Rocket plume** (`missile_thruster`, `ship_thruster`):
  - a white-hot core and an orange-red scrolling flame cone with heat distortion;
  - three or four flickering Mach diamonds, flame puffs cooling from yellow to red, and sparks;
  - a red-orange glow, and a reddish-grey smoke trail that slows, swells and drifts.
- **The ship thruster block** used to draw vanilla flames and smoke on the client
  (`ShipThrusterBlockEntity.clientPlume`). The server now sends the Effekseer plume instead. The
  client draws the vanilla plume only when `effekseerEnabled` or `effekseerShipThrusters` is off;
  both flags are synced to clients (protocol 100).
- **Sparking** (`sparking_aura`, `sparking_burst`):
  - a gold ki veil with flame strands and tongues, crawling lightning, rising embers, a ground dust
    ring and rock chips;
  - at the start, a gold flash, a ground shockwave, a lightning burst, a rock spray and a dust
    cloud.

  The vanilla Sparking aura (`SparkingAuraFx`: dust ring, flame, block debris, electric sparks) is
  the fallback when the effect does not play.
- **`/xenofx play <slot> [scale]`** (op 2) plays any slot at the block you look at, facing your
  look. `/xenofx list` names the slots.

## Hakai effects (generated, 2026-09-28)

The four Hakai slots are generated, not stand-ins. `tools/effekseer/gen_hakai_effects.py` draws
their textures, writes Effekseer projects, and compiles them with the Effekseer 1.80.6 editor
headless (`Effekseer.exe -cui -in <project> -o <out.efkefc>`). Re-run it after editing:

    python tools/effekseer/gen_hakai_effects.py --effekseer <folder with Tool/bin/Effekseer.exe>

The look follows Dragon Ball Super, where Beerus erases Zamasu:

- A purple veil clings to the victim. It has a dark violet coating and bright violet energy
  scrolling upward, with magenta crackling edges, flame strands and rising lilac motes.
- The body vanishes from the head down (the existing client wipe, `hakaiFadeSpeed` /
  `hakaiFadeBand`). Violet shards and dust tear away at that line and drift upward.
- The erase is a soft violet flash with no explosion. The last shards and wisps float away.
- The caster's palm carries a small flickering purple flame.

The script checks that the editor kept every value it wrote. The editor saves back only values it
understood, so a misspelt element fails the run. The editable projects are in
`tools/effekseer/hakai/<slot>/`, and they open in the Effekseer editor.
`tools/effekseer/efkefc2xml.py` turns any `.efkefc` back into project XML.

While these effects play, the vanilla Hakai dust, the particle silhouette and the caster aura are
off. They return as the fallback when effects are off or fail.

## Server config (`XenoServerConfig`)

| Key | Default | Range |
| --- | --- | --- |
| `effekseerEnabled` | `true` | Master switch |
| `effekseerPunches` / `effekseerHakai` / `effekseerMissiles` | `true` | Per category |
| `effekseerRange` | `64` | 8 to 512 blocks: punches and Hakai |
| `effekseerMissileRange` | `256` | 8 to 2048 blocks: missiles |
| `effekseerPunchesPerTick` | `24` | 1 to 512, server-wide |
| `effekseerPunchScale` | `0.3` | 0.05 to 3: size of the punch effects (heavy hits are 1.6x) |
| `effekseerHakaiScale` | `1.0` | 0.05 to 5: size of every Hakai effect (on top of body size) |
| `effekseerMissileScale` | `1.0` | 0.05 to 5: size of missile thrusters and explosions |
| `effekseerSparking` / `effekseerShipThrusters` | `true` | Sparking effects / ship thruster plumes (off: vanilla) |
| `effekseerSparkingScale` / `effekseerThrusterScale` | `1.0` | 0.05 to 5 |
| `effekseerExplosionScale` | `15` | 0.05 to 50: missile explosion size (every warhead) |
| `<effect>` (for example `missile_explosion`, `sparking_flight`; also `fxscale_<effect>`) | `1.0` (`sparking_flight` 3.5) | 0.05 to 50: that one effect's size, on top of its category size. For `missile_thruster`, above 1 also moves the flame's start behind the tail |

All of these are `/xenoset` keys, for example `/xenoset effekseerPunchScale 0.5` or
`/xenoset effekseerHakaiScale 1.3`. Aliases: `punchsize`, `hakaisize`, `missilesize`,
`effekseer`, `punchfx`, `hakaieffek`, `missilefx`, `effectrange`, `missilefxrange`, `punchcap`,
`sparkingfx`, `thrusterfx`, `sparkingsize`, `thrustersize`.
The body wipe runs over the whole channel, so a slower Hakai is `/xenoset hakaiChannelTicks 80`.

**No double punches.** A target gets at most one punch effect per tick. Basic punches are queued
and played at the end of the tick, only when no combo, charge or guard effect already covered that
target; they never add vanilla particles or cues. Every effect is positional, so the ranges
always apply.

## Authoring your effects (Effekseer editor, `tools/new_particles/Effekseer1.80.6Win`)

- **Punches (Budokai Tenkaichi 3 style).** A white-gold core flash (2–4 frames), radial spikes, and
  a thin expanding shockwave ring. Total about 0.3 s. `punch_heavy` adds a second ring and a short
  distortion.
- **Missile explosion.** A flash, a fireball, turbulent grey smoke and sparks with gravity,
  2–4 s.
- **Missile thruster.** A pulse about 0.5 s long: a white core, an orange flame cone and a smoke
  trail. It is re-sent every 8 ticks while the motor burns.
- Keep textures at power-of-two sizes, 512 px or less. Do not use HDR-only materials.

## Code

| Class | Role |
| --- | --- |
| `fx/effek/XenoEffects` | Server entry point: `attempt(level, slot, pos, forward, scale, targetId)` returns PLAYED, DUPLICATE (draw nothing extra) or UNAVAILABLE (draw the vanilla particles); `play` is `attempt == PLAYED`. |
| `fx/effek/EffectGate` | Config switches, ranges, the per-tick punch cap, one punch per target per tick |
| `fx/effek/AaaEffekSender` | The only class that calls AAA Particles, using its common API only (`ParticleEmitterInfo`, `AAALevel`) |
| `fx/effek/PunchEffectEvents` | Basic DMZ melee hits: queued on `LivingDamageEvent.Post`, played on `ServerTickEvent.Post` |
| `CombatFx`, `HakaiFx`, `BallisticMissileEntity`, `ShipBallisticTicker` | The call sites |

**Tests.** AAA Particles patches `ResourceLocation` validation and looks up its platform helper
through the thread's context class loader. In the test worker that is the JVM app loader, so
`testsupport/AaaParticlesTestInit` (auto-registered through `junit-platform.properties`) starts the
helper once with the mod class loader, as the game does.
