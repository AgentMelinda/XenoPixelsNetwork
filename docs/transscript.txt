  # DMZ UI Studio, AI Brain v4/v5, and Xeno NPC Foundation

  ## Summary

  - Preserve and extend the current untracked UI/NPC work rather than replacing it; record the dirty tree and restrict
    edits to explicitly reviewed paths.

  - First resolve all nine findings from xenopixels-code-review.md, which is byte-identical to the external Grok
    worktree copy.

  - Upgrade the DMZ UI Studio with true multi-selection, a layers hierarchy, precise movement/resizing, locking,
    visibility, snapping, grouping, and gesture-level undo.

  - Add AI Brain v4 for MyNPCs and CustomNPCs; add AI Brain v5 exclusively for native Xeno NPC entities.
  - Ship a native NPC vertical slice with generic humanoid/creature entities plus separate trader, guard, companion,
    and quest entity types.

  - Add a Xeno NPC Wand with dedicated DMZ-styled menus and safe, one-way legacy-NPC import. Imports never modify or
    delete the original NPC.

  ## Implementation Changes

  ### 1. Review and Safety Fixes

  - Make plot purchases transaction-safe: revalidate the listing and owner immediately before settlement, perform
    compensating rollback on partial failure, and return a distinct reconciliation failure if rollback itself fails.

  - Make MmoEconBridge fail closed unless both balance and money APIs resolve; select reflected overloads by
    compatible parameter types, preserve boolean/status returns, and log resolution failures without exposing player
    data.

  - Declare the optional mmoecon dependency, consolidate the duplicate Create dependency block, and simplify the
    misleading ballistic-controller ternary.

  - Refuse late shop-sign auto-registration when ownership cannot be established; require a legitimate sign edit or
    explicit administrative repair instead of persisting an ownerless shop.

  - Replace the seven reviewed catch (Throwable) sites with the narrow expected exceptions and rate-limited debug/
    warning logs.

  - Keep these fixes as a separately reviewable change set before beginning the studio and NPC work.

  ### 2. DMZ UI Studio

  - Replace the single selectedId state in UiStudioSession with an ordered selection set and primary selection while
    preserving convenience methods for single-selection callers.

  - Add editor-only node metadata for locked and editor-hidden state; runtime visibility remains separate and
    serialized independently.

  - Add a real layers panel synchronized with the canvas and inspector:
      - Hierarchical rows with depth, name, type, visibility, lock, and selection state.
      - Shift-click ranges, Ctrl-click toggling, search/filter, rename, reorder, reparent/unparent, duplicate, group/
        ungroup, and delete.

      - Draw order follows hierarchy order; locked or editor-hidden elements cannot be canvas-selected.

  - Improve canvas interaction in DmzGuiStudioScreen:
      - Topmost-element hit testing with click cycling for overlapping elements.
      - Drag-box selection and Shift/Ctrl selection modifiers.
      - Eight resize handles plus a group bounding box for multiple selections.
      - Group movement and proportional group resizing while preserving each child’s relative position.
      - Arrow-key nudging; Shift uses the current snap size and Ctrl temporarily disables snapping.
      - Snap to grid, canvas edges/centers, parent edges/centers, sibling edges/centers, and safe-area bounds.
      - Visible selection outlines, element labels, parent bounds, snap guides, and distinct locked/hidden styling.

  - Treat an entire pointer gesture as one undo command. Inspector changes, reorder operations, grouping, duplication,
    visibility, and lock changes also receive undo/redo entries.

  - Use a three-pane DMZ layout—layers, canvas, inspector—at large resolutions, with collapsible/tabbed side panels at
    smaller GUI scales.

  - Extract selection, geometry, snapping, hierarchy, and undo behavior into Minecraft-independent classes so focused
    unit tests do not require a client.

  - Preserve existing UI JSON compatibility by assigning defaults when the new editor metadata is absent.

  ### 3. AI Brain v4 and v5

  - Extend NpcCombatBrainVersion from v1–v3 to v1–v5 with stable stored values 4 and 5; old or unknown stored values
    continue to fall back safely.

  - Introduce an internal shared brain contract:
      - Immutable combat-context snapshot.
      - Intent/decision result with target, movement, skill, and cooldown requirements.
      - Host adapter for reading state and executing approved actions.
      - Per-entity memory/blackboard with bounded expiry.
      - Budgeted scheduler and deterministic random source for testing.

  - Implement v4 as the legacy integration engine for both MyNPCs and CustomNPCs:
      - Port the verified context and decision hierarchy from ai-brain.md: target validity, distance bands, resource
        state, health, locomotion, blocking, reaction locks, skill readiness, combo pools, and repositioning.

      - Route actions only through existing verified combat helpers such as melee, ki dispatch, forms, flight,
        animations, and target control.

      - Keep optional mod classes behind their existing separate MyNPCs/CustomNPCs adapters and mixins.
      - Expose v4 in both legacy Combat/Brain tabs with grouped pages for awareness, movement, defense, melee, ki,
        transformations, cooldowns, and debugging.

  - Implement v5 only for native Xeno NPCs:
      - Reuse the v4 decision vocabulary, but run through native components rather than reflected legacy fields.
      - Add bounded threat memory, role policy, squad/owner context, target persistence, and native pathing controls.
      - Prevent legacy NPC profiles from selecting v5; decoding v5 on a legacy host falls back to v4 and reports the
        correction in the editor.

  - Performance defaults:
      - No level-wide entity scans during ordinary NPC ticks.
      - At most 32 high-level brain decisions globally per server tick.
      - Combat decisions every 10 ticks, alert/non-combat decisions every 20 ticks, and dormant checks every 40 ticks.
      - Expensive path recalculation no more than once per 10 ticks per NPC unless the target becomes invalid.
      - Event-driven cache invalidation on target death, unload, dimension change, profile update, and NPC removal.
      - Keep animation/combo advancement separate from high-level decisions so active attacks remain responsive.

  ### 4. Native Xeno NPC System

  - Add a shared component-driven XenoNpcEntity foundation and register these first-milestone types:
      - Generic humanoid.
      - Generic creature.
      - Trader.
      - Guard.
      - Companion.
      - Quest NPC.

  - Specialized entity types supply default body family and role policy, while all persistent features live in
    reusable components rather than duplicated subclasses.

  - Initial components:
      - Identity, display name, ownership, permissions, and provenance.
      - Appearance/body family and DMZ-compatible visual profile.
      - Stats, inventory/equipment, combat profile, and v5 brain state.
      - Job/role policy, faction membership, dialogue references, quest references, and companion owner/mode.
      - Versioned persistence and dirty-state tracking.

  - Initial functional role behavior:
      - Guard: configurable defended owner/faction/area and hostile-target policy.
      - Companion: owner binding plus follow, stay, defend, and passive modes.
      - Trader: persistent trade-definition reference and interaction entry point.
      - Quest NPC: persistent dialogue/quest-definition references and interaction entry point.
      - Generic humanoid/creature: editable neutral foundation without forced role behavior.

  - Store per-entity state in versioned entity NBT. Store reusable dialogue, quest, faction, trade, appearance, and
    role definitions as codec-validated datapack JSON under the XenoPixels namespace.

  - Maintain event-driven server indexes for UUID, owner, faction, role, and nearby-active NPCs; never rebuild indexes
    by scanning every loaded entity.

  - Keep this system internal during the first milestone. Do not add unstable classes under the published api/**
    compatibility surface.

  ### 5. Xeno NPC Wand and Menus

  - Register xeno_npc_wand with a resource-pack item model, localization, recipe/creative-tab entry, DMZ-styled
    texture, and six matching role/body icons.

  - Produce one reviewable image-generation concept sheet for the wand and role icons, then convert selected concepts
    into pixel-aligned shipping PNGs with verified dimensions and resource locations.

  - Wand behavior:
