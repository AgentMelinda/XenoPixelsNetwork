## Full dedicated-server archive check

Inspected `C:\Users\Admin\Downloads\Compressed\XenoPixels - DragonMineZ - Server.zip` on `2026-09-25`. It contains 164 mod jars and no world/map directory. Its server targets Minecraft `1.21.1` and NeoForge `21.1.248`; the relevant mods are Sable `2.0.5`, C2ME `0.4.0-alpha.0.122`, Chunky `1.4.23`, and Fast Noise `1.0.13+1.21.1`. The archive does not include ScalableLux.

The failure is the interaction between the max-height pack and Fast Noise. The pack changes the overworld dimension type to `min_y=-2032`, `height=4064`, while retaining vanilla overworld noise settings (`min_y=-64`, `height=384`). Fast Noise's `FastWorldgen.populateNoise` computes section indexes as `(blockY - minimumY) >> 4`. Chunk section arrays start at the world's minimum build height, so passing the noise minimum produces the observed 123-section offset. The compatibility mixin now passes the world minimum as the section-index base when the entire noise range fits inside the world. This keeps Fast Noise's optimized writer and avoids the prior slow vanilla fallback for this expanded-height case. Vanilla fill remains the safe path when the noise range extends beyond the world's build bounds.

The existing datapack fix makes both height packs available but not auto-selected, while leaving `xeno_ship_masses` on its previous default. The compatibility mixin is gated on `zfastnoise`. For matching ranges it preserves the original values; for an expanded world that contains the noise range it adjusts only the section-index base; ranges extending outside the world use Minecraft's vanilla `doFill` path.

On `2026-09-25`, a disposable NeoForge `21.1.248` server reached `Done` and Chunky generated and saved 9 overworld chunks. That run did not inspect the generated block palettes or measure generation time, so it does not verify the terrain fix or its performance. The revised section-base correction has passed its focused automated test and packaging build; a fresh generated-region inspection and timing comparison remain unverified.

The runtime test used the original server mod jar with only the rebuilt `ModDatapacks.class` inserted. This was necessary because the existing, user-modified `neoforge.mods.toml` in the working tree sets optional MMO Econ to `[1.1.0,)`, while this server archive has MMO Econ `1.0.5`; using the complete newly-built server jar therefore aborts mod loading on that version check. The user's metadata change was preserved. Update MMO Econ or resolve that version constraint before installing a complete new XenoPixels server jar into this specific archive.

These fixes affect chunks generated after installing the updated mod jar. They do not rewrite chunks already saved with misplaced terrain. Existing broken chunks need a deliberate world recovery or recreation plan.
